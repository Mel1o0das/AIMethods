# BookingService Frontend

Frontend существующего сервиса бронирования бань и глэмпингов. Проект использует Next.js App Router и сохраняет два изолированных режима данных: локальную демонстрацию для ДЗ №4 и API-адаптер для последующей интеграции с Backend в ДЗ №5.

В рамках ДЗ №4 студент последовательно выполнил четыре итерации с использованием Codex: подготовил воспроизводимую сборку и Mock-слой, переработал главную и каталог, завершил сценарии создания и отмены заявки, затем провёл финальную регрессию и оформил отчётные материалы. Исходные промпты и результаты каждой итерации сохранены в [`docs/homework-4`](docs/homework-4).

## Стек и требования

- Next.js 16.4.2, React 19.2.4, TypeScript strict;
- Ant Design 6.3.7;
- Vitest 3 и React Testing Library;
- рекомендуемая среда разработки: Node.js 22.13 LTS или новее из поддерживаемой LTS-линейки, npm 10/11.

Next.js требует Node.js `>=20.9.0`, но часть текущей ESLint-цепочки требует как минимум `20.19.0` в ветке Node 20. Поэтому установленный на исходной машине Node.js `20.17.0` запускает проект, но выдаёт `EBADENGINE`; для воспроизводимой разработки рекомендуется Node 22 LTS.

## Установка и запуск

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

`.env.local` не должен попадать в Git.

Пример локальной конфигурации:

```dotenv
NEXT_PUBLIC_DATA_MODE=mock
# NEXT_PUBLIC_API_BASE_URL=http://localhost:5260/api
```

После изменения `NEXT_PUBLIC_DATA_MODE` dev-сервер необходимо перезапустить.

## Режимы данных

### Mock

```powershell
$env:NEXT_PUBLIC_DATA_MODE="mock"
npm run dev
```

Mock-режим использует вымышленные типизированные данные и фиксированного пользователя без административных прав. Каталог, занятость, заявки и демо-авторизация не выполняют HTTP-запросы. Заявки хранятся только в памяти JavaScript-модуля: клиентские переходы сохраняют их, а полная перезагрузка страницы сбрасывает состояние.

Баннер в интерфейсе сообщает, что реальные заявки не создаются. Числовое поле цены показывается как условная демонстрационная сумма: единица тарификации Backend пока не подтверждена.

### API

```powershell
$env:NEXT_PUBLIC_DATA_MODE="api"
$env:NEXT_PUBLIC_API_BASE_URL="http://localhost:5260/api"
npm run dev
```

API-режим сохраняет существующие сервисы и JWT-поток. Запущенный Backend для ДЗ №4 не требуется, а фактическая интеграция, OpenAPI-контракты, серверная проверка пользователя/статуса, `409 Conflict` и политика timeout относятся к ДЗ №5.

## Основные маршруты

- `/` — главная и переход к поиску;
- `/objects` — каталог, фильтры, сортировка и пагинация;
- `/objects/[id]` — карточка объекта и форма демо-заявки;
- `/my-bookings` — собственные заявки и отмена;
- `/login`, `/register` — настоящий API-поток авторизации;
- `/admin`, `/admin/bookings` — сохранённые административные страницы API-режима.

## Три сценария ДЗ №4

1. Поиск на главной → каталог → фильтры по типу, условной цене и вместимости → сортировка/пагинация → карточка объекта.
2. Выбор будущего свободного интервала и числа гостей → создание имитационной заявки → явный success и переход в личный кабинет.
3. Просмотр только своих Mock-заявок → подтверждение отмены → статус «Отменено» → освобождение интервала.

Mock-адаптер проверяет будущую дату, `start < end`, вместимость, владельца отмены и пересечения полуоткрытых интервалов `[start, end)`. Примыкающие интервалы допустимы. Прошедшая заявка доступна только для просмотра и не отменяется.

## Проверки

```powershell
npm run lint
npx tsc --noEmit
npm test

$env:NEXT_PUBLIC_DATA_MODE="api"
npm run build

$env:NEXT_PUBLIC_DATA_MODE="mock"
npm run build

npm audit --omit=dev
```

Последний подтверждённый полный прогон завершился следующим образом:

- `npm run lint` — код 0, без ошибок и предупреждений;
- `npx tsc --noEmit` — код 0;
- `npm test` — код 0, 7 файлов и 21/21 пройденный тест;
- production-сборка с `NEXT_PUBLIC_DATA_MODE=api` — код 0;
- production-сборка с `NEXT_PUBLIC_DATA_MODE=mock` — код 0;
- `npm audit --omit=dev` — код 0, production-уязвимости не найдены.

Тесты покрывают Mock-каталог, отсутствие HTTP, создание и конфликт заявок, примыкание интервалов, защиту от двойной записи, валидацию, владельца отмены, освобождение слота, демо-авторизацию и UI-состояния ошибки/повтора/отмены. Полный `npm audit` при этом остаётся диагностическим ограничением: он сообщает о 12 уязвимостях в dev/test-зависимостях.

## Известные ограничения

- Mock-состояние сбрасывается при полной перезагрузке.
- Суммы условные; тариф за час/сутки не подтверждён.
- Время бань и глэмпинга основано на явно подписанных демонстрационных допущениях.
- Доступность в Mock не является подтверждением реального сервера.
- В репозитории сохранены настоящие desktop-снимки и два снимка viewport 528 px. Отдельная ручная матрица 375/390/430/768/1280 CSS px, клавиатуры и focus restoration не выполнялась; автоматические jsdom-тесты не проверяют геометрию.
- Нельзя публиковать приложение как production-сервис до проверки Backend и актуального security audit.
