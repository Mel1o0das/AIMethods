# ДЗ №4 — итерация 01: воспроизводимая сборка и Mock-слой

Дата: 16.10.2026 (Europe/Moscow)

## Точный промпт итерации

> Подготовь **существующий Frontend BookingService** к работе над ДЗ №4. **Не делай полный редизайн и не переписывай страницы пока.** Начни с воспроизводимой сборки и архитектуры локального Mock-режима для следующих этапов.
>
> 1. Ознакомься с `../reference/technical_specification.md`, двумя PNG-макетами концепции №2 и структурой `src/app`.
> 2. Проверь установку зависимостей, `npm run lint`, `npm run build`, типизацию; зафиксируй ошибки до правок. Не отключай проверки, чтобы скрыть ошибки.
> 3. Проверь прямые импорты сторонних пакетов. В частности, `src/app/components/BookingFormModal.tsx` импортирует `dayjs`, а в исходном `package.json` он не объявлен напрямую. При необходимости исправь с согласованным lock-файлом.
> 4. Спроектируй **изолированный переключаемый Mock-режим** для каталога, занятости и заявок. Реализуй минимальную основу (типизированные Mock-данные, слой переключения источника данных или адаптер), при этом не ломай реальные сервисы API и не трогай Backend. Не допускай случайных реальных HTTP-запросов в Mock-режиме.
> 5. Добавь базовую инфраструктуру автоматических тестов, совместимую с React 19 / Next.js 16 (например, Vitest + React Testing Library), а также команды запуска тестов в `package.json`. Пока достаточно небольших тестов Mock-логики/утилит; функциональные UI-тесты будем добавлять на следующем этапе.
> 6. Подготовь краткий план следующей итерации: редизайн главной и каталога по концепции №2, три проверяемых пользовательских сценария с Mock-данными, затем адаптивность и тестирование.

Дополнительные условия промпта: соблюдать `AGENTS.md`, не изменять Backend, сохранить маршруты, зафиксировать риск подавления ошибок в `src/app/objects/page.tsx`, не объявлять проект готовым до реализации трёх сценариев, адаптивности и проходящих тестов.
