Не исходи из того, что архивы из прежних итераций совпадают с текущим кодом. Не трогай Backend, PostgreSQL и не меняй API-контракты ради демонстрации.
Подтверждённый контекст
По отчёту предыдущей итерации lint, tsc, две production-сборки (api/mock) и npm test прошли, всего 16/16 тестов; это не заменяет повторной проверки. Пользователь сам проверил Mock-режим и прислал скриншоты: каталог с шестью объектами, карточку объекта, окно создания заявки, раздел «Мои бронирования», успешное создание booking-demo-2 на будущий интервал, появление новой заявки и отмену этой заявки со статусом «Отменено». На мобильных скриншотах ширина 528 CSS px, а не 375/390. Скриншот не доказывает фактическое освобождение слота, невозможность повторного бронирования занятого времени, клавиатурную доступность или отсутствие проблем на всех ширинах.
Существующий Mock-профиль вымышленный и не имеет админских полномочий. Demo-данные хранятся только в памяти и после полной перезагрузки сбрасываются; это согласованное ограничение ДЗ №4, а не баг, который нужно скрывать. Реальный Backend на этом этапе не используется.

1. На разных страницах часть кнопок и ссылок осталась синей по умолчанию Ant Design (/objects/[id], модальное окно, success, «Мои бронирования», пагинация). Сохранить визуальную ясность destructive-действия «Отменить». Проверить hover, focus-visible, disabled, error, success. Не использовать глобальное переопределение, ломающее admin/API-режим.
2. Сейчас на всех карточках одна CSS-иллюстрация домика. Сохрани проект автономным: не добавляй произвольные горячие ссылки и не копируй фото из чужих макетов. Если доступны разрешённые локальные изображения — аккуратно используй отличающиеся изображения для объектов, с alt, адаптивными размерами и fallback. Если нет — оставь иллюстрацию, зафиксируй как косметическое ограничение, но не объявляй, что фотографии добавлены.
3. В демонстрационных данных есть booking-demo-1 с прошедшим 14–16 июля 2026 года интервалом, но статус «Подтверждено» и действие «Отменить заявку». Устрани противоречие без изобретения статусов настоящего Backend: либо сделай соответствующий будущий демо-интервал, либо показывай такую запись как историю без отмены (только если уже поддерживается моделью). Дату «сегодня» не захардкоживай; при необходимости вводи детерминированные часы/тестовую дату. В отчёте поясни выбранное решение. Не разрешай отмену прошедшей заявки, если это не согласованное явное правило.

B. Доказать правильность трёх пользовательских сценариев
6. Проверить: / → /objects?search=... → фильтрация по типу/цене/гостям → сортировка и пагинация → /objects/[id]. loading, реальный empty, error + retry различаются и не подменяют друг друга. При переключении фильтров ожидаемо сбрасывается страница пагинации, если нужно.
7. Создание Mock-заявки: дата в будущем, start < end, не больше вместимости, атомарная проверка пересечения [start,end) внутри mock-data-source; примыкание интервалов разрешено, пересечение отклонено.
