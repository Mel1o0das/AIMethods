# Промпт для v0 — концепция 3 «Удобный каталог»

Создай качественный интерактивный UI-прототип сервиса бронирования бань и глэмпингов **BookingService**. Проект уже существует на Next.js/React; сейчас нужен отдельный сравнительный прототип редизайна Frontend, не перенос реального Backend. Используй локальные demo-данные, никаких API, оплат, внешней авторизации, базы или секретов. Язык интерфейса — русский, цены в ₽. Сделай responsive для desktop 1440 px и mobile 390 px.

**Общий сценарий:** просмотр каталога → фильтрация → выбор объекта → проверка свободных дат/часов → отправка демо-заявки. В отличие от двух остальных концепций, приоритет здесь — максимальная скорость выбора и очевидные элементы управления.

**Уникальная дизайн-концепция № 3: функциональный booking marketplace.** Светлый UI, белый и светло-серый #F8FAFC, насыщенный синий #1E5A86 для CTA, бирюзовый #207E81 для доступности, нейтральный тёмно-серый текст. Минимум декоративных hero-блоков, строгая сетка, привычные контролы, чёткая иерархия информации. Это продуктовый рабочий интерфейс, а не туристический лендинг.

**Композиция desktop, принципиально отличающаяся от концепций № 1 и № 2:**
- Компактная верхняя панель: BookingService, «Каталог», «Мои бронирования», «Войти».
- Сразу под шапкой — **полноширинная поисковая строка**: тип («Бани / Глэмпинги / Все»), дата начала, дата конца / время, число гостей, кнопка «Найти».
- Под поиском двухколоночный рабочий макет: **постоянная боковая панель фильтров слева** (тип, максимальная цена, количество гостей, кнопка «Сбросить фильтры»), а справа список результатов с заголовком «Найдено 6 вариантов», сортировкой и карточками.
- Карточки показывай **горизонтальными строками** с фото слева, названием, типом, вместимостью и кратким описанием в центре, ценой и кнопкой «Выбрать» справа. Внутри карточки можно показать понятную нейтральную метку «Доступность уточняется»; не выдавай mock-данные за проверенную реальную доступность.
- По нажатию «Выбрать» справа открывается **панель бронирования с календарём и списком временных слотов**, каталог остаётся видимым на фоне. Для бани показывай выбор даты, начала и окончания по часам; для глэмпинга — даты въезда и выезда.
- Для занятых временных интервалов явно используй disabled-состояние и текст «Занято»; показывай валидацию гостей, отсутствия дат и состояние конфликта «Время уже занято. Выберите другой интервал».
- Пагинация или кнопка «Показать ещё» внизу результатов.

**Те же демонстрационные объекты:** «Купольный домик у озера» (глэмпинг, 2 гостя, 8 500 ₽/ночь), «Баня на дровах» (баня, 6 гостей, 2 500 ₽/час), «Домик „Сосны“» (глэмпинг, 4 гостя, 11 000 ₽/ночь), «Баня „Лесная“» (баня, 4 гостя, 2 100 ₽/час), «Сфера среди сосен» (глэмпинг, 2 гостя, 9 200 ₽/ночь), «Баня у ручья» (баня, 8 гостей, 3 000 ₽/час). Все данные демонстрационные.

**Mobile:** header компактный, параметры поиска сгруппированы, фильтры открываются через нижний drawer с кнопкой «Применить», результаты в одну колонку, цена и CTA остаются заметны, календарь бронирования открывается на весь экран. Никакого горизонтального скролла всей страницы.

**Поведение:** фильтры, сортировка и поиск работают по mock-данным; карточки открывают панель бронирования; есть empty/loading/error состояния. Видимые focus-состояния и доступные подписи элементов. Отдельно продумай компактную мобильную структуру, а не просто сожми десктоп.

Не добавляй оплаты, отзывы, карты, рейтинги, личный кабинет как отдельную страницу, программу лояльности или новую бизнес-логику. Используй Next.js App Router + React + TypeScript для демонстрационного Preview. Главная цель этой концепции — понятный рабочий поиск и бронирование за минимум действий.
